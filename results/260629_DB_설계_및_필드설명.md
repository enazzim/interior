## 2. 테이블별 필드 설명 및 설계 의도

### 2.1. `materials` (자재 및 노무비 마스터 사전) 테이블
* **설계 의도:** 자재와 노무비의 원가 단가를 엄격하게 하나의 마스터 테이블에서 물리적으로 구분하고 격리 등록할 수 있도록 튜닝되었습니다.
* **필드 설명:**
  * `material_id` (PK, Long): 자동 번호 생성
  * `material_name` (String, Not Null): 품목명 (예: `고급 이태리 포세린 타일`, `타일공 시공 인건비`)
  * `specification` (String) **[신설]**: 규격 및 상세 사양 정보 (예: `600x600`, `실크`, `기공 1인`)
  * `item_type` (String) **[신설]**: 품목 구분 값 (`MATERIAL` = 순수 자재비, `LABOR` = 순수 노무/인건비)
  * `standard_unit` (String): 실측/소요 기본 단위 (㎡, m, L, 일 등)
  * `distribution_unit` (String): 발주/유통 단위 (Box, Roll, 일 등)
  * `conversion_rate` (Double): 단위 환산율 (1개 유통 단위당 실측 크기. 노무비인 경우 `1.0` 고정)
  * `purchase_price` (Double): 순수 자재 매입 원가 (자재 구분일 때만 활성, 노무비는 0)
  * `labor_price` (Double): 순수 노무/인건비 단가 (노무비 구분일 때만 활성, 자재비는 0)

### 2.2. `projects` (공사 현장) 테이블
* **설계 의도:** 현장 진행 수명 주기를 제어하고 완료 시의 영구 데이터 변경 방지 락의 앵커 포인트로 활용됩니다.
* **필드 설명:**
  * `project_id` (PK, Long): 자동 번호 생성
  * `project_name` (String, Not Null): 현장 공사명
  * `address` (String): 공사 주소지
  * `status` (String, Default '견적중'): 진행 상태 (`견적중` ➔ `수주` ➔ `공사중` ➔ `완료`)
    * **중요 로직:** `status` 가 `완료` 로 갱신되는 순간, 이 테이블 및 연관된 `estimates`, `estimate_items` 데이터는 화면과 API 상에서 수정 및 추가가 전면 차단(Lock)됩니다.

### 2.3. `estimate_items` (견적서 상세 항목) 테이블
* **설계 의도:** 견적서가 최종 엑셀/PDF로 인쇄될 때 각 공정과 자재/노무비 행을 개별 레코드로 출력하기 위해 규격과 타입을 마스터 시점에서 영구 스냅샷으로 백업 기입합니다.
* **필드 설명:**
  * `estimate_item_id` (PK, Long): 자동 번호 생성
  * `estimate_id` (FK, Long): 상위 견적 마스터 키
  * `material_name` (String): 당시 품명 스냅샷
  * `specification` (String): 당시 규격 스냅샷
  * `item_type` (String): `MATERIAL` / `LABOR` 구분 스냅샷
  * `calculated_qty` (Double): 단위 환산 및 마진 계산이 반영된 청구 수량
  * `customer_unit_price` (Integer): 최종 고객 청구 단가
