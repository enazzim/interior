# 2026-06-29 [계획서] 모바일 클라우드 사진 연동, 통계 대시보드 및 가상 스크롤(Virtual Scroll) 구축

본 계획서는 모바일 클라우드 사진 1:N 업로드 연동, 소상공인 인테리어 업체의 흑자 부도를 완벽하게 예방해 주는 4대 핵심 경영 통계 시스템 및 대용량 목록 조회 시 브라우저 성능 렉을 원천 방지하는 가상 스크롤(Virtual Scroll) 구축을 위한 통합 개발 계획서입니다.

---

## 1. 파트 A: 모바일 클라우드 사진 1:N 업로드 연동

### 1.1. 데이터베이스 스키마 및 엔티티 설계 (Step 1)
하나의 공정(`Process`) 또는 프로젝트 현장(`Project`) 아래 여러 장의 사진을 매핑할 수 있는 `1:N` 관계형 구조를 수립합니다.
* **[NEW] `ProjectImage.java` (Entity):**
  * `Long imageId` (PK), `String imageUrl` (S3 저장경로 URL), `String originalFileName`
  * `@ManyToOne` ➔ `Project project` (현장)
  * `@ManyToOne` ➔ `Process process` (공정 대분류, Optional)

### 1.2. 백엔드 파일 업로드 API 개발 (Step 2)
* **AWS S3 연동:** `build.gradle` 의 `spring-cloud-starter-aws` 의존성 주입
* **[NEW] `ProjectImageController.java`:**
  * `POST /api/projects/{projectId}/images`: 다중 이미지 파일 수급 및 S3 업로드/DB 주소 기록
  * `GET /api/projects/{projectId}/images`: 등록된 사진 목록 조회

### 1.3. 모바일 반응형 파일 업로더 컴포넌트 구현 (Step 3 & 4)
* **[NEW] `ImageUploader.tsx`:** HTML5 `<input type="file" accept="image/*, application/pdf" multiple />` 를 통해 모바일 기기 구동 시 사진 갤러리 앨범 및 기기 내 도면 파일 자동 수급
* **PWA 모바일 최적화 레이아웃:** 폰으로 조작하기 쉽도록 복잡한 그리드를 배제하고 상단에 사진 촬영 및 업로드 버튼 배치

### 1.4. 견적 시뮬레이터 및 엑셀 사진 첨부 자동화 (Step 5)
* 엑셀 파일 내보내기 시 Apache POI의 `Drawing` 기능을 확장하여 두 번째 시트에 공정별 시공 전후 사진첩 레이아웃을 자동 인쇄되게 통합합니다.

## 2. 파트 B: 4대 핵심 경영 통계 대시보드 구축

### 2.1. 백엔드 집계 API 설계 (Step 6)
데이터베이스의 현장, 지출, 정산 내역을 Group By 연산하여 통계용 정제 데이터를 제공하는 통계 컨트롤러를 구축합니다.
* **[NEW] `StatisticsController.java` / `StatisticsService.java`:**
  * **`GET /api/stats/margin`**: 현장별 기대 마진 대비 실제 지출을 계산하여 순이익이 높은 우수 현장 랭킹 반환
  * **`GET /api/stats/aging`**: 미수금 및 미지급금의 결제 연체 일수별 통계 반환 (`30일 이내`, `60일 이내`, `90일 초과` 연령 분석)
  * **`GET /api/stats/vendor`**: 누적 거래 거래액이 가장 높은 자재상 및 협력 반장님 통계 반환
  * **`GET /api/stats/process`**: 전체 자금 지출 중 타일, 목공, 도배 등 공정 대분류별 지출 점유 비중 반환

### 2.2. 프론트엔드 통계 시각화 대시보드 화면 구현 (Step 7 & 8)
* **[NEW] `StatisticsDashboard.tsx`:** 차트 전문 라이브러리(`Recharts`)를 활용하여 가로 막대 그래프, 누적 막대 그래프, 원형 그래프 시각화 구축 및 대표자 전용 인가 라우터 가드 보강

## 3. 파트 C: 대용량 데이터 렉 방지를 위한 가상 스크롤 (Virtual Scroll) 도입

### 3.1. 도입 배경 및 목표 (Step 9)
* **배경:** 수천 개의 자재 마스터 데이터나 수백 개의 현장 목록이 쌓였을 때, 브라우저가 모든 DOM 요소를 렌더링하면 심각한 화면 끊김(렉)과 메모리 낭비가 발생합니다.
* **목표:** 사용자의 가시 영역(Viewport)에 해당하는 최소한의 항목(예: 10~20개)만 돔에 활성화하고, 스크롤 이동 시 보이지 않는 영역의 노드를 즉시 교체(Recycle)하여 성능을 O(1) 수준으로 극대화합니다.

### 3.2. 세부 구현 대상 및 기법 (Step 10)
* **대상 1: `MasterData.tsx` (자재 사전 그리드 테이블)**
  * 자재 사전 리스트 출력 시 고정 높이(`rowHeight`)를 활용한 커스텀 가상 테이블 렌더러 적용
* **대상 2: `EstimateBuilder.tsx` (자재 자동완성 검색 리스트)**
  * 자재명 검색 시 수백 개 매칭 목록이 드롭다운에 쏟아질 때 부드러운 스크롤 스핀을 보장하기 위해 드롭다운 컨테이너 가상화 적용
* **구현 기법:**
  * 리스트 전체 가상 높이를 `totalCount * rowHeight` 로 예약 지정
  * 스크롤 이벤트(`scrollTop`)에 기초하여 가시 범위 시작 인덱스(`startIndex`) 및 종료 인덱스(`endIndex`) 계산
  * 해당 가시 영역에 여유 분량(buffer)을 더한 항목들만 `slice` 하여 절대 좌표(`top: index * rowHeight`)로 스택 렌더링
